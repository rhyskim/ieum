# ADR-0008: 아카이브 타임라인과 이모지 리액션

- 상태: **확정** (2026-11-18, 오너 답 + 스키마 변경 승인)
- 날짜: 2026-11-18
- 학습 노트(옵시디언): `개발/Ieum/학습/0009-답변-공개-상태머신과-리액션.md` (Part D)

## 맥락
`answer_reactions`에 유일 제약이 없다(V1). 이모지 5종(LOVE, TOUCHED, THANKS, FUNNY, HUG)과 Phase 2의 음성 리액션이 한 테이블을 쓴다.

## 오너의 답
| # | 답 | 판정 |
|---|---|---|
| D-1 | 같은 이모지 두 번 누르면 취소, 흔한 앱 방식 | ○ 서버 API는 멱등하게 |
| D-2 | UNIQUE로 중복 방지 | ○ 맞음, 단 현재 제약 없음 |
| D-3 | 공개 전 금지, 탈퇴자는 "(탈퇴한 사용자)" | ○ |
| 추가 | 한 사람이 여러 종류 가능, 본인 답변에도 가능 | 확정 |

## 최종 결정
1. 한 사람이 한 답변에 여러 종류의 이모지를 달 수 있다. 같은 종류는 1건이다: `UNIQUE(answer_id, user_id, emoji_code)`. 음성 리액션은 이모지와 구분되는 **부분 유니크 인덱스**로 따로 정한다(Phase 2).
2. API는 멱등하게 둔다: 달기는 `PUT`(이미 있으면 그대로, `INSERT ... ON CONFLICT DO NOTHING`), 취소는 `DELETE`(없으면 그대로). 앱이 화면 상태를 보고 토글처럼 보이게 한다.
3. **서버 권한**: 공개 전 답변에는 리액션할 수 없다(서버가 거절). 요청자는 유효 멤버여야 하고, 시간 초과 공개라면 본인이 답변을 마쳤어야 한다. 본인 답변에도 달 수 있다.
4. 탈퇴한 사용자의 답변·리액션은 그대로 보인다. 리액션 목록의 작성자는 "탈퇴한 사용자"(보는 사람이 정한 호칭이 있으면 그것)로 표시한다(ADR-0002 결정 14).
5. 타임라인은 `cycle_date` 내림차순 **커서(키셋) 페이징**이다(안정 정렬을 위해 id 보조 정렬).
6. **스키마 변경 승인(번호는 그때의 다음 번호)**: `answer_reactions` 유일 제약 추가(기존 중복 정리 포함). 번호는 먼저 머지되는 쪽이 사용한다.
7. 참고 디자인: `image/ref1~3.png`(오너 제공). 분위기만 참고하고 형태·캐릭터·아이콘·문구는 복제하지 않는다. 글자 대비·크기는 CLAUDE.md §5를 우선한다.
