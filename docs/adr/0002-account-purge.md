# ADR-0002: 탈퇴 파기와 계정 연결 (account)

- 상태: 확정
- 날짜: 2026-11-17 (추가 결정 2026-11-18)

## 맥락
ADR-0001이 탈퇴 요청과 30일 복구까지 정했다. 이후 파기 배치, 탈퇴 시 콘텐츠 처리, 계정 연결, Apple 토큰 해지가 남았다. `family_groups.creator_id`, `group_invites.inviter_id`가 `users`를 FK로 참조해 사용자 행을 그대로 삭제할 수 없다.

## 결정
1. **파기 방식**: 익명화(tombstone). `users` 행은 남기고 이름·이메일·전화번호를 지우고 `PURGED`로 표시한다. `user_identities`, `refresh_tokens`, `user_devices`는 삭제한다.
2. **계정 연결**: 이미 다른 계정에 가입된 소셜 계정은 병합하지 않고 거절+안내한다(409). 마지막 로그인 수단은 해제할 수 없다. 제공자당 하나만 연결한다(`UNIQUE(user_id, provider)`).
3. **콘텐츠 선택**: 탈퇴 요청 시 "상대에게 계속 공개 / 영구 삭제"를 선택해 저장하고, 실제 처리는 파기 시점에 실행한다. 리액션은 유지한다. 작성자는 "탈퇴한 사용자"로 표시하되, 보는 사람이 정한 별칭이 있으면 그것을 쓴다(ADR-0003의 호칭 모델).
4. **방장 탈퇴**: ADR-0003의 위임 규칙을 따른다.
5. **Apple 해지 실패**: 나머지 파기는 계속하고, 해지만 간격을 늘려 가며 재시도한다.
6. **복구와 파기 경쟁**: 복구 마감은 탈퇴 후 30일, 파기 시작은 31일 이후. 복구와 파기 시작은 같은 행에 대한 조건부 UPDATE로 한쪽만 성공시킨다.
7. **파기 배치**: ShedLock으로 서버 간 중복 실행을 막고, 사용자 1명 단위로 멱등 단계를 처리한다. 외부 자원(S3, Apple)을 먼저, DB는 마지막에 처리한다.
8. 복구 시 그룹이 이미 20명이면 그 그룹의 멤버십은 `LEFT`로 바꾼다. 혼자 남은 그룹은 파기 시점에 해산(`archive`)한다. 스키마 변경 V5(탈퇴 콘텐츠 선택, `purge_started_at`/`purged_at`, Apple 해지 큐, `UNIQUE(user_id, provider)`)를 적용한다. 익명화 시 NOT NULL 컬럼(`users.name`, `group_members.family_nickname`)에는 '탈퇴한 사용자'를 넣는다.
9. **파기 순서**: 음성(S3) 삭제 → DB 한 트랜잭션에서 익명화와 완료 표시. 서버가 중간에 죽으면 처음부터 다시 실행해도 안전하도록 모든 단계를 멱등으로 설계한다(`purge_started_at`은 처리 중 임대 표시, 30분 후 이어받기).
10. **중복 실행 방지**: ShedLock(서버 간) + 사용자 단위 조건부 UPDATE(2중 방어). 복구 마감 30일, 파기 시작 31일 이후로 구조적으로 겹치지 않게 하고, 조건부 UPDATE는 시계 차이에 대한 이중 방어로 둔다.
11. **유효 멤버 정의**: 코드 한 곳(공통 쿼리 조각 `VALID_USER`)에서만 정의하고 모든 쿼리가 그것을 쓴다. 기존 파생 쿼리 메서드는 제거해 우회로를 없앤다. DB 뷰는 만들지 않는다.
12. **복구 시 상한 충돌**: 그룹 행 `FOR UPDATE`로 승인과 같은 줄을 서고, 여러 그룹은 id 오름차순으로 잠가 교착을 피한다.
13. **Apple 해지 재시도**: 큐에 쌓고 지수 백오프(10분×2^(n−1), 최대 24시간, ±20% 지터, 최대 8회 후 `FAILED`). 해지 실패는 나머지 파기를 막지 않는다. 이번 구현체는 키가 없어 "미설정 → 건너뜀"으로 기록한다.
14. **영구 삭제(DELETE) 범위**: 본인이 쓴 답변(텍스트·음성 S3)만 삭제한다. 본인이 남에게 단 리액션은 선택과 무관하게 유지한다. 삭제되는 답변에 달린 남의 리액션은 답변이 사라지므로 함께 사라진다. 계속 공개(KEEP)는 아무것도 지우지 않는다.
15. **방장 파기 위임**: 방장이 파기될 때 그룹에 유효 멤버가 있으면 가장 오래된 유효 멤버(joined_at, id 순)에게 방장을 위임한다. 유효 멤버가 없으면 기존 "혼자 남은 그룹 해산" 규칙을 따른다.
16. **복구 시 방장 부재 보정**: 복구하는 사용자의 그룹에 유효 방장이 없고 비어 있는 방장 자리가 파기된 사용자의 행이면 복구자가 방장이 되고, 파기된 사용자의 방장 플래그는 해제한다. 방장이 단지 탈퇴 유예 중이면 승격하지 않는다(복귀 권리 존중, 그가 파기되면 결정 15로 이어진다).

## 근거와 트레이드오프
- **익명화 vs 행 삭제**: 외래 키가 사용자 행을 참조하므로 삭제 대신 익명화한다. 개인정보는 제거하고 관계 정보만 남긴다.
- **계정 병합 거절**: 두 계정의 콘텐츠·그룹을 합치는 비용과 위험이 크다. v1에서는 거절하고 안내한다.
- **외부 작업은 DB 롤백으로 되돌릴 수 없다**: S3 삭제와 Apple 해지는 한 트랜잭션에 넣을 수 없으므로 멱등 단계와 상태 컬럼(임대)으로 처리한다.
- **복구 vs 파기 경쟁**: 복구가 이긴다. 파기 시작에 하루 여유를 두고 조건부 UPDATE로 한쪽만 성공시킨다.
- **유효 멤버 정의를 한 곳에**: 쿼리마다 조건을 반복하면 하나만 빠져도 탈퇴한 사람이 노출된다.
