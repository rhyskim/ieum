# Task: answer (텍스트 답변 + 공개 상태 머신)

- 브랜치: `feat/answer` / worktree: `.worktrees/answer`
- 대상: backend 먼저(이 작업의 핵심). 모바일은 같은 PR에서 "오늘의 질문 → 답변 작성 → 공개 여부 표시"의 최소 화면만.
- 선행: question(머지됨). 알림은 ADR-0004 이벤트 패턴 재사용.

## 목표
멤버가 오늘의 질문에 텍스트로 답하고, 전원이 답하거나 17시가 지나면 서로의 답변이 공개된다. 동시에 마지막으로 저장해도 공개가 누락되지 않는다.

## 범위
- 답변 저장/수정 API(`groupId`·`dailyQuestionId` 경로). 본문은 공백 제외 30자 이상(수정도 동일), 한 사용자당 질문 1개 답변(`UNIQUE(daily_question_id, user_id)`는 이미 있음). 마감 없음: 지난 질문에도 언제든 답할 수 있다.
- 저장 트랜잭션은 `daily_questions` 행을 `FOR UPDATE`로 잠근 뒤 답변 저장과 미답변 수 확인(분모=유효 멤버, ADR-0002)을 한다. 전원 답변이면 `UPDATE ... WHERE reveal_status='LOCKED'`로 `REVEALED_ALL` 전환, 전환이 1행일 때만 "모두가 답변을 마쳤어요" 푸시(커밋 후 비동기, 개인정보 없음).
- 혼합형 공개: 상태는 저장하되 조회·저장 시점에 `auto_reveal_at`이 지났고 답변이 1명 이상이면 같은 조건부 UPDATE로 `REVEALED_TIMEOUT` 전환. 아무도 답하지 않은 채 17시가 지나면 LOCKED 유지(질문 건너뜀), 이후 첫 답변이 들어오면 즉시 TIMEOUT 전환. 전원 답변이 시간 초과보다 우선.
- 조회 API: 오늘의 질문 상세(+멤버별 `hasAnswered`·호칭), 질문별 답변 목록. **서버 마스킹**: LOCKED 동안 타인 답변 본문은 응답에 포함하지 않는다. REVEALED_TIMEOUT은 본인이 답변을 마친 멤버에게만 타인 답변을 준다.
- 멤버가 빠지는 사건(탈퇴 요청·강퇴·나가기) 후 해당 그룹의 LOCKED 질문에 공개 조건 재평가(전원 답변 충족 시 전환).
- 15시 리마인드·17시 공개 푸시는 이 작업 범위 밖(후속). 질문 도착 푸시 탭 시 이동 경로(`QUESTION_ASSIGNED` → 해당 그룹 오늘의 질문 화면)를 모바일 `push_routing`에 추가.

## 범위 밖
음성 답변(Phase 2), 리액션·타임라인(archive), 15시 리마인드, 알림 설정, 디자인 톤 적용.

## 수용 기준 (테스트로 표현)
- [ ] 두 멤버가 동시에 마지막으로 저장해도 정확히 한 번 REVEALED_ALL로 전환되고 푸시는 1회(동시성 테스트, 반복 실행).
- [ ] LOCKED 동안 타인 본문은 API 응답에 없다(본인 답변만 보임).
- [ ] 17시 이후 조회/첫 답변으로 TIMEOUT 전환, 0명이면 LOCKED 유지, 이후 첫 답변에서 즉시 TIMEOUT. 시각은 Clock 주입.
- [ ] TIMEOUT 상태에서 답변하지 않은 멤버는 타인 답변을 볼 수 없고, 답변한 뒤 볼 수 있다.
- [ ] 30자 미만(공백 제외) 저장·수정은 거절된다. 공개 후 수정해도 상태는 유지.
- [ ] 탈퇴 유예·탈퇴·강퇴로 분모가 줄어 조건을 충족하면 공개로 전환된다.
- [ ] 비멤버·탈퇴 유예 사용자는 조회·저장이 거절된다.
