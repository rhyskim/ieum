# ADR-0005: 소셜 로그인 SDK 연동과 토큰 검증

- 상태: 확정
- 날짜: 2026-11-18

## 맥락
서버 쪽 토큰 검증(ADR-0001, `KakaoTokenVerifier` 등)은 구현·테스트되어 있으나 앱에는 소셜 SDK가 없어 실제 로그인이 불가능했다(`SOCIAL_SDK_NOT_CONFIGURED`).

## 결정
1. **제공자**: 카카오·네이버를 앱에 연동한다. Apple은 서버 검증 코드를 유지하되 앱 연동은 iOS 출시 시점으로 미룬다.
2. **흐름**: SDK가 앱에서 토큰을 받아 서버 `POST /api/v1/auth/{provider}`로 보낸다. 서버가 제공자에 다시 확인한다(카카오는 `app_id` 일치까지). 앱은 서버 응답을 신뢰 근거로 삼고 SDK 토큰을 신뢰 근거로 삼지 않는다.
3. **실패 처리**: 사용자 취소는 오류가 아니다(조용히 로그인 화면 유지). 토큰 만료·위조는 `INVALID_SOCIAL_TOKEN`으로 앱이 SDK 토큰을 1회 재발급해 재시도한다. 제공자 장애·타임아웃은 `SOCIAL_PROVIDER_UNAVAILABLE`로 구분해 "잠시 후 다시 시도"를 안내하고 서버는 재시도하지 않는다.
4. **iOS/Apple**: Google Play에는 Apple 로그인 의무가 없다. App Store는 다른 소셜 로그인을 제공하면 개인정보 보호 요건을 만족하는 동등한 로그인 수단을 요구하므로(가이드라인 4.8) iOS 출시 시 Apple 로그인이 필요하다. 따라서 Android를 먼저 출시하고 iOS는 후속으로 둔다.
5. **키·콘솔 등록**은 개발자가 직접 하며 키는 커밋하지 않는다(`--dart-define`/로컬 파일, gitignore).

## 근거와 트레이드오프
- **제공자별 검증 방식**: 카카오·네이버는 불투명 토큰이라 제공자 API로 확인하고, Apple은 JWT라 공개키(JWKS)로 서명·`iss`·`aud`·`exp`·`nonce`를 검증한다.
- **토큰 대체 공격 방지**: 다른 앱에서 발급된 정상 토큰을 보내도 `app_id`가 다르면 거절한다.
- **인증 실패와 외부 장애 구분**: 둘을 같은 401로 주면 앱이 장애 때 사용자를 로그아웃시키는 버그가 생긴다.
- **네이버 SDK**: 공식 Flutter SDK가 없어 커뮤니티 패키지를 쓴다(라이선스·유지보수 기준으로 선택, 근거는 PR #7).

## 결과·후속 작업
작업지시서 `docs/tasks/social-login.md`, 키 주입 방법 `docs/social-login-keys.md`. 네이버는 검수 승인 전에는 등록한 테스트 계정만 로그인될 수 있다.
