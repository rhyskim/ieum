# Task: group-core

- 브랜치: `feat/group-core` / worktree: `.worktrees/group-core`
- 대상: backend + mobile (PLAN 1-2 중 코드 입장. 링크는 `invite-link.md`로 보류)
- 근거: `docs/adr/0003-group-invite.md`, `docs/adr/0002-account-purge.md`(방장 위임, 익명화). 어긋나면 구현하지 말고 Root에 묻는다.

## 목표
가족 그룹을 만들고, 6자리 코드로 입장을 요청하고, 방장이 승인하면 멤버가 된다. 무차별 대입을 막고, 보는 사람마다 다른 호칭을 쓴다.

## 범위
Backend (모든 API는 `groupId` 컨텍스트와 `@GroupMemberOnly`/방장 검사를 거친다)
- 그룹 생성(생성자는 방장 + `ACTIVE`), 내 그룹 목록(N:M), 그룹 상세(멤버, 내가 정한 호칭).
- 코드: 방장이 발급(`SecureRandom` 6자리, 앞자리 0 보존, 유효 5분 설정값). 그룹당 활성 1개(재발급 시 이전 폐기). 중복은 유니크 위반 시 재시도.
- 입장 요청(코드 입력) → `PENDING`. 이미 `PENDING`/`ACTIVE`면 성공으로 응답(멱등). 코드가 없거나 만료면 안내 오류. 입장 전에는 그룹 정보를 응답에 싣지 않는다.
- 방장: 승인 대기 목록 조회, 승인/거절, 강퇴. 승인 대기는 2일 후 만료. 승인 시점에 인원 20명 상한을 잠금으로 보장(21번째 동시 승인 불가). 초과 시 `GROUP_FULL`.
- 이탈/강퇴 후 재입장은 같은 행을 이어 쓴다(`LEFT`는 새 요청으로 `PENDING`, `REMOVED`는 코드로 재입장 불가).
- 방장 이탈: 위임 대상 지정 가능, 없으면 가장 오래된 `ACTIVE`(가입 일시 → id). 혼자면 그룹 해산. 같은 로직을 탈퇴 흐름이 재사용할 수 있게 서비스 메서드로 분리한다.
- 입장 시도 제한: 사용자별 5분 5번 실패 → 20분 잠금(429, 남은 시간 포함). 잠금 3회 누적(기간은 설정값, 기본 24시간) → 이상 사용자 기록(`security_events`) + 에러 로그. 자동 차단 없음. 수치는 모두 설정값.
- 호칭: `member_aliases(group_id, viewer, target, alias)`, 조회·설정 API. 호칭이 없으면 상대가 입장 때 정한 이름을 쓴다.
- 상한 도달 시 관리자 연락: 메시지를 `support_requests`에 저장하는 API(전달은 DB 저장까지).
- 방장에게 입장 요청이 오면 알림 포트(`GroupNotifier` 인터페이스)를 호출한다. 구현체는 이번엔 로그 전용이고 FCM은 `notification` 작업.
- Flyway `V3`(오너 승인 필요): 활성 코드 부분 유니크 인덱스, `member_aliases`, `group_members`에 방장 표시·`PENDING`/`REMOVED` 상태, 입장 시도 상태, `security_events`, `support_requests`.

Mobile
- 그룹 목록/전환, 그룹 만들기, 코드 보기(큰 숫자, 남은 시간, 새로 만들기, 공유 시트로 코드 전달), 코드 입력(숫자 키패드), 승인 대기 화면("방장이 확인하고 있어요" 등 친절한 문구), 방장의 승인 대기 목록, 멤버·호칭 편집, 상한 도달 시 관리자 문의 화면. 접근성 규칙(루트 CLAUDE.md §5) 준수.

## 범위 밖
링크·딥링크, FCM 실제 발송(`notification`), 탈퇴 파기·계정 연결(`account`), 질문·답변, IP 기반 제한.

## 수용 기준 (테스트로 표현)
- [ ] 생성자는 방장이며, 코드는 6자리 숫자이고 활성 코드는 그룹당 1개다. 같은 시점 활성 코드끼리 중복되지 않는다.
- [ ] 만료/없는 코드는 입장 불가, 유효 코드는 `PENDING`이 되고 응답에 그룹 정보가 없다.
- [ ] 같은 사용자의 동시 2건 입장 요청 → 행 1개, 둘 다 성공 응답.
- [ ] 방장 승인 시 `ACTIVE`, 방장이 아니면 거부(403). 다른 그룹 방장의 승인도 거부.
- [ ] 19명 방에 동시 승인 2건 → 정확히 1건만 성공하고 20명을 넘지 않는다.
- [ ] 5분 내 5번 실패 → 20분 잠금(429). 잠금 3회 누적 → `security_events` 기록. 잠금 중에는 유효 코드도 거부.
- [ ] `REMOVED`는 코드로 재입장 불가, `LEFT`는 `PENDING`으로 재요청 가능.
- [ ] 방장 이탈 시 지정자에게, 없으면 가장 오래된 `ACTIVE`에게 위임(동률은 id 순). `PENDING`은 후보 제외. 혼자면 해산.
- [ ] 호칭은 보는 사람마다 독립적이며 다른 그룹·다른 사용자 것은 조회·수정 불가.
- [ ] 승인 대기는 2일 후 만료 처리되며 만료된 요청은 승인할 수 없다.
- [ ] 모바일: 코드 입력/잠금/승인 대기/상한 도달 화면 위젯 테스트(한글 라벨, 56dp).

## 오너 확정 (2026-11-17)
- 입장 시도 제한 저장소는 **PostgreSQL**(Redis 사용 안 함). 트래픽이 늘면 재검토.
- `REMOVED`(강퇴)는 코드로 재입장 불가. 거절된 사용자는 다시 요청할 수 있다.
- 문의 메시지는 DB 저장까지만(전달 채널 없음).
- Flyway `V3` 스키마 변경 **승인됨**. 기존 `V1`, `V2`는 수정하지 않는다.
