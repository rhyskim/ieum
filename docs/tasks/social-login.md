# Task: social-login

- 브랜치: `feat/social-login` / worktree: `.worktrees/social-login`
- 대상: mobile 중심 + backend 소폭(설정·오류 구분)
- 선행: auth(머지됨). 외부 준비: 카카오·네이버 앱 등록과 키 발급은 **오너가 한다**(키는 커밋 금지).

## 목표
앱에서 카카오·네이버 로그인으로 실제 JWT를 받아 로그인·복구·로그인 수단 연결이 동작하게 한다.

## 범위
- 모바일 SDK 연동(카카오, 네이버)을 `SocialTokenProvider` 구현체로 추가하고 기존 `SOCIAL_SDK_NOT_CONFIGURED` 기본 구현을 키가 없을 때의 대체로 유지한다. 로그인·복구·연결 화면이 같은 공급자를 쓴다.
- 사용자 취소는 오류 화면 없이 로그인 화면에 머문다. 토큰 만료·위조(`INVALID_SOCIAL_TOKEN`)는 SDK 토큰을 1회 재발급해 재시도, 제공자 장애(`SOCIAL_PROVIDER_UNAVAILABLE`)는 "잠시 후 다시 시도" 안내(자동 재시도 없음).
- 백엔드: 네이버 검증기와 카카오 `app_id` 설정이 `docs/adr/0005`와 맞는지 확인하고, 인증 실패와 제공자 장애 응답 구분을 테스트로 고정한다(없으면 추가).
- 키 주입 방식 문서화(`--dart-define`/로컬 설정, gitignore). Apple은 이번 범위 밖.

## 범위 밖
Apple 로그인 앱 연동(iOS 출시 시), 실제 상용 키 등록, 소셜 프로필 동기화.

## 수용 기준 (테스트로 표현)
- [ ] 가짜 `SocialTokenProvider`로 로그인·복구·연결 성공 흐름이 위젯 테스트로 통과한다.
- [ ] 사용자 취소는 에러 표시 없이 로그인 화면에 남는다(테스트).
- [ ] 401(토큰 문제)과 502/503(제공자 장애)가 앱에서 서로 다른 안내로 매핑된다.
- [ ] 백엔드: 다른 앱의 카카오 토큰(`app_id` 불일치)은 거절, 제공자 타임아웃은 장애 응답(테스트).
- [ ] 키가 없는 환경에서도 앱이 기동하고 로그인 버튼이 명확한 안내를 보인다.
