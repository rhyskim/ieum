# ADR-0004: 푸시 알림(FCM) 발송 방식과 기기 토큰

- 상태: 확정
- 날짜: 2026-11-18

## 맥락
그룹 입장 요청을 방장에게 푸시로 알리고, 승인·거절 결과를 요청자에게 알린다. 초기 `user_devices`는 `UNIQUE(user_id, fcm_token)`이라 같은 토큰이 서로 다른 사용자 행에 존재할 수 있었다. 푸시는 보조 채널이고 앱 안의 목록(DB)이 기준이다.

## 결정
1. **발송 설계**: 서비스는 알림 대상 정보만 담은 이벤트를 발행하고, `@TransactionalEventListener(AFTER_COMMIT)` + 전용 스레드풀 `@Async`로 발송한다. FCM 호출에는 타임아웃을 둔다(연결 3초, 읽기 5초). 일시 오류(`UNAVAILABLE`, `INTERNAL`)에만 짧게 제한적으로 재시도하고(최대 3회, 500ms 간격), `UNREGISTERED`는 토큰을 삭제한다(`REQUIRES_NEW`). 발송 예외는 로그만 남기고 업무 트랜잭션에는 영향이 없다. 아웃박스는 만들지 않는다(서버 크래시 시 알림 1건 유실 수용). 알림 문구·data에는 개인정보를 넣지 않는다(고정 문구와 `type`, `groupId`만).
2. **토큰 소유**: 토큰은 한 번에 한 사용자에게만 속한다. 등록 시 같은 토큰의 다른 사용자 행은 upsert로 소유를 이전하고, 로그아웃 시 그 기기 토큰을 삭제하며, DB 제약 `UNIQUE(fcm_token)`을 최종 방어선으로 둔다(`UNIQUE(user_id, fcm_token)`을 대체). 같은 계정의 여러 기기는 각각 별도 토큰으로 두고 모두에게 보낸다.
3. **알림 문구의 호칭 사용 (2026-11-24 보완)**: 17시 공개 알림에 한해, 수신자가 직접 정한 가족 호칭(`member_aliases`)과 "누가 답했는지"를 문구에 넣을 수 있다. 답변 내용, 실명, 이메일·전화번호는 여전히 넣지 않으며 data에는 `type`·`groupId`만 둔다. 호칭은 푸시 전달 경로(FCM)를 거치고 잠금 화면에 보일 수 있으므로 길이를 제한하고(최대 3명, 초과는 "외 N명") Phase 3 알림 설정에서 "알림에 이름 표시 끄기"를 제공한다.

## 근거와 트레이드오프
- **FCM은 종단 간 ACK가 없다**: FCM은 "접수"만 응답하므로 재전송은 스팸이 되고 ACK/WatchDog 방식은 맞지 않는다. 신뢰성은 DB 상태(앱 안 목록)로 얻고, 타임아웃은 FCM 호출 구간에만 적용한다.
- **커밋 후 비동기 발송**: 트랜잭션 안에서 외부 호출을 하면 커밋 전에 알림이 나가거나(롤백 시 거짓 알림) FCM 지연이 DB 커넥션을 붙잡는다.
- **토큰 소유 이전**: 같은 기기에서 계정을 바꿔 로그인했을 때 이전 계정에 알림이 가는 일을 막는다.

## 결과·후속 작업
- 스키마 변경 V4(`UNIQUE(fcm_token)`).
- 작업지시서: `docs/tasks/notification.md`.
- 호칭 사용(결정 3): 이점은 알림에 관심을 유도하는 것이고, 비용은 잠금 화면 노출과 FCM 경유다. 답변 내용을 포함하지 않고 별명 수준이라 허용하되 이름 표시 끄기 옵션을 후속으로 둔다.
