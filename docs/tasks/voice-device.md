# Task: voice-device (온디바이스 TTS·STT 연동)

- 브랜치: `feat/voice-device` / worktree: `.worktrees/voice-device`
- 대상: mobile 전용(서버 변경 없음)
- 선행: answer(머지됨). `core/voice`의 `TtsService`·`SttService` 인터페이스와 기본(Noop) 구현이 이미 있다.

## 목표
질문을 소리로 들을 수 있고, 말하면 답변 입력창에 글자가 채워진다. 키보드 없이도 텍스트 답변을 쓸 수 있는 첫 단계다.

## 범위
- `TtsService`의 온디바이스 구현(`flutter_tts`): 질문 카드의 "질문 듣기" 버튼(한글 라벨 병기), 재생/정지 토글, 속도 0.85배(느리게)·1.0배 전환. 화면을 벗어나면 정지. 한국어 음성이 없는 기기에서는 버튼을 비활성화하고 이유를 안내.
- `SttService`의 온디바이스 구현(`speech_to_text`): 답변 작성 화면의 "말해서 쓰기" 버튼을 누르면 인식 결과가 입력창에 실시간으로 채워진다. 사용자가 고칠 수 있고 저장은 기존 텍스트 답변 API를 그대로 쓴다. 변환 결과는 단지 입력창의 초안이며 서버 규칙(공백 제외 30자 이상, 2000자 이하)은 바뀌지 않는다.
- 마이크 권한 요청: 거부·영구 거부·미지원 기기·인식 서비스 오류를 각각 안내하고 앱이 죽지 않는다(영구 거부는 설정 열기 안내).
- 접근성 불변식: 본문 18sp 이상, 터치 48dp 이상(주요 56dp), 아이콘 버튼에 한글 라벨.
- 플랫폼 설정: Android 권한·쿼리, iOS는 Info.plist 설명 문구를 추가하되 iOS 실행은 이번 범위 밖이므로 설정 추가만 한다.

## 범위 밖
원본 음성 녹음·업로드·재생(voice-recorder와 이후 작업), 음성 답변을 서버에 보내는 흐름, 클라우드 STT, 디자인 톤 변경.

## 수용 기준 (테스트로 표현)
- [ ] 가짜 TTS/STT 서비스를 주입한 위젯 테스트: 듣기 버튼이 재생/정지로 바뀌고 화면을 벗어나면 정지 호출이 된다. 속도 전환이 서비스에 전달된다.
- [ ] 가짜 STT의 부분·최종 결과가 입력창에 반영되고, 기존 텍스트를 지우지 않으며(이어 붙이기 정책을 PR에 명시), 수정 후 저장 요청은 기존 API 계약 그대로다.
- [ ] 권한 거부·영구 거부·미지원·오류 각각에서 안내가 나오고 예외가 전파되지 않는다.
- [ ] `flutter analyze`, `flutter test`가 키 없는 환경에서 통과한다.
