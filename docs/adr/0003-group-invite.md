## 열린 결정
1. **방장이 그룹을 나가거나 탈퇴하면?** (위임 / 최장 멤버 승계 / 해산) — ADR-0002와 함께.
2. **입장 승인**: 코드 입력 즉시 열람 가능 vs 방장 승인 후 활성화 vs 입장 직후 방장 알림만(오너 안). 입장 전 정보를 전혀 보여주지 않기로 해서, 오타로 남의 방에 곧바로 들어갈 수 있다는 점을 고려해야 한다(추천: 방장 승인 후 활성화).
3. **Rate limit 수치**: 예) 사용자당 10분 5회 실패 → 잠금, IP별 보조, 코드 유효기간 48시간. 카운터 저장소(Redis 추천).
4. **인원 상한 20명 동시 입장 처리**: 21번째가 동시에 들어오지 못하게 하는 방법(그룹 행 잠금 vs 조건부 삽입)은 구현 전 오너와 정한다. 상한 도달 시 관리자에게 연락하는 메시지의 전달 경로(메일 앱 열기 vs 서버 저장)도 정한다.
5. **링크 방식과 단계**: 도메인·유니버설 링크·디퍼드 딥링크는 범위가 크다. 1단계=코드 입력+공유 시트로 코드 전달, 2단계=링크. 이렇게 나눌지.
6. **강퇴자 재입장**: 코드로 재입장 불가(추천) / 방장이 허용.
7. **호칭 모델**: 신규 `member_aliases(group_id, viewer, target, alias)`. 기존 `family_nickname`의 역할(입장 시 자기 이름?)과 기본 표시 우선순위.
8. 스키마 변경(V3): 활성 코드 부분 유니크 인덱스, `member_aliases`, 멤버 상태에 `REMOVED`, (링크 도입 시) `invite_links`.

## 확정된 부분 (2026-11-17)
- 입장 승인: **방장 승인 후 활성화**.
- 방장 탈퇴·이탈: 탈퇴 시점에 위임 대상을 정할 수 있고, 기본값은 **가장 오래된 멤버**(가입 일시 동률이면 저장 순서).
- 입장 시도 제한: **5분에 5번 실패 시 잠금**. 수치는 설정값으로 둔다.
- 코드 유효기간: **5분**(설정값, 추후 변경 가능). 만료되면 재발급한다.
- 링크 기능은 1단계에서 같이 구현한다. 인원 상한 20명, 상한 도달 시 관리자 연락 화면, 입장 전 그룹 정보 비공개는 위 표대로.

## 최종 결정 (2026-11-17, 오너 확정)
1. **입장 승인**: 6자리 코드로 들어오면 `PENDING`이 되고 방장이 승인하면 `ACTIVE`가 된다. 승인 대기는 **2일** 후 만료된다. 방장에게 알림을 보낸다(푸시는 보조, 앱 안의 승인 대기 목록이 기준).
2. **코드**: 유효기간 5분(설정값), 그룹당 활성 코드 1개, 기간 내 다회용, `SecureRandom`, 활성 코드끼리만 유니크.
3. **입장 시도 제한**: 5분에 5번 실패 시 **20분 잠금**. 20분 잠금에 **3번 걸린 사용자는 이상 사용자로 간주**해 관리자에게 보고한다(자동 차단은 하지 않는다).
4. **방장 위임**: 탈퇴·이탈 시점에 직접 지정하고, 기본값은 가장 오래된 `ACTIVE` 멤버(가입 일시 → id 순으로 결정). 탈퇴 요청 즉시 적용되고 복구해도 방장은 자동으로 돌아오지 않는다. 혼자 남은 방장의 방은 해산한다.
5. **링크**: 이번 범위에서 **제외**한다. 확정한 사양(유효기간 18시간, 1회용, 방장 승인 생략, 수락 요청에서만 소진)은 `docs/tasks/invite-link.md`에 보류 상태로 보관한다. 출시 후 이용률을 보고 도메인 구매와 함께 결정한다.
6. **인원 상한 20명**, 입장 전 그룹 정보 비공개, 호칭은 보는 사람마다 따로 저장(`member_aliases`).
7. **상한 도달 시**: 관리자에게 연락하는 메시지 화면을 제공한다(특수 방은 수동 대응).
8. 스키마 변경(V3)은 오너 승인 후 진행한다.
