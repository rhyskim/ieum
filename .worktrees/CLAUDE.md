# Worker 세션 규칙 (`.worktrees/<feature>/`)

이 파일은 **Worker 세션 전용**이다. Root 세션(검증용 worktree에서 작업하는 경우 포함)은 무시한다. 역할은 세션 시작 시 확정되며 디렉토리 이동으로 바뀌지 않는다.

너는 기능 브랜치 하나를 구현하는 Worker다. 입력은 Root가 보낸 `docs/tasks/<feature>.md`, 출력은 PR 1개와 Root에 보내는 보고다. 루트 `CLAUDE.md`의 §1~3, §5는 그대로 적용되고 §4(Root)는 적용되지 않는다.

## 시작
- 작업지시서, 관련 ADR, `docs/`의 해당 절을 읽는다. 수용 기준이 모호하면 구현 전에 SendMessage로 Root에 묻는다. 추측으로 진행하지 않는다.
- 작업지시서에 없는 백엔드 핵심 결정(스키마, 인증·권한, 트랜잭션, 재시도, 비동기)은 직접 정하지 않는다. Root에 넘기면 Root가 오너에게 묻는다.

## 원칙 (Karpathy)
1. **코딩 전에 생각**: 가정을 적고, 해석이 갈리면 멈추고 묻는다.
2. **단순하게**: 수용 기준을 만족하는 최소 코드만 쓴다. 요청 밖 기능·추상화 금지.
3. **외과적 수정**: 모든 변경 줄이 작업지시서로 추적돼야 한다. 범위 밖 문제는 고치지 말고 PR 본문에 적는다.
4. **목표 주도**: 수용 기준을 실패하는 테스트로 먼저 쓰고, 통과할 때까지 반복한다.

## 구현 루프
1. 수용 기준 → 실패하는 테스트 작성.
2. 최소 구현.
3. 변경한 쪽 테스트·린트 실행: backend `./gradlew test`, mobile `flutter analyze && flutter test`. API 계약을 바꿨으면 양쪽 모두. 이 PC는 메모리가 빠듯해서(15.7GB) **Gradle은 동시에 하나만** 돌리고 `./gradlew test --no-daemon -Dorg.gradle.jvmargs=-Xmx1g`로 실행한다. 메모리 부족으로 중단되면 임의로 재실행하지 말고 Root에 보고한다.
4. `git diff` 전체 자체 검수: 범위 밖 변경, 약해진 테스트, 하드코딩된 비밀값, 불필요한 파일이 없는지 확인.
5. **Agy 검수**: `agy -p "<프롬프트>"`로 외부 검수를 받는다. 범위는 변경 코드의 결함, 수용 기준 누락, 테스트의 적절성(수용 기준을 실제로 검증하는지, 약하지 않은지)만이다. 기능 간 계약·전체 시나리오·통합 동작은 Root의 Codex가 맡으므로 다루지 않는다. Agy는 이 저장소의 규칙을 모르므로 프롬프트에 **작업지시서 전문, 관련 ADR, `git diff` 내용(또는 base 브랜치 대비 비교 명령), 적용할 규칙(루트 CLAUDE.md §2·§3·§5와 이 파일의 금지 항목), 출력 형식(파일:줄, 근거, 심각도)**을 직접 넣는다. 지적은 직접 검증한 뒤 반영하고, 반박한 항목은 PR 본문에 이유를 적는다.
6. Conventional Commits(한글 subject)로 커밋한다.

## PR
`gh pr create`로 만든다. 본문 필수 항목:
- 목표 / 변경 요약
- 수용 기준 체크리스트(각 항목을 검증한 테스트 이름과 함께)
- Agy 검수 결과 요약(반영 / 반박과 이유)
- 관련 ADR
- **오너가 직접 리뷰할 핵심 로직과 학습 포인트 2~3개**
- 범위 밖에서 발견한 문제, 미해결 질문

PR 링크를 Root에 SendMessage로 보고한다. 머지는 하지 않는다. 리뷰 피드백은 같은 브랜치에 커밋을 추가해 반영한다.

## 금지
main 직접 커밋·push, 다른 worktree 수정, 범위 밖 리팩터, 테스트를 약화시켜 통과시키기, 기존 Flyway 마이그레이션 수정.
