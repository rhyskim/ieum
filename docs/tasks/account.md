# Task: account

- 브랜치: `feat/account` / worktree: `.worktrees/account`
- 대상: backend + mobile (탈퇴 요청 개편, 30일 후 파기, 유예 중 표시 규칙, 계정 연결, 복구 화면)
- 근거: `docs/adr/0002-account-purge.md`(확정), `docs/adr/0001-auth-jwt.md`, `docs/adr/0003-group-invite.md`. 어긋나면 구현하지 말고 Root에 묻는다.
- 선행: auth, group-core(머지됨). 방장 위임 메서드(`GroupMembershipService` 등)를 재사용한다.

## 목표
탈퇴를 요청하면 30일 동안 복구할 수 있고, 31일째 이후 개인정보를 익명화한다. 유예 중에는 가족에게 보이지 않는다. 한 계정에 여러 로그인 수단을 연결한다.

## 확정된 규칙
- **유예 중(탈퇴 요청~복구/파기)**: 다른 가족 화면에서 이 사람은 보이지 않는다. 그룹 인원 수·상한 20명·방장 후보에서도 제외된다(-1로 반영). 과거 답변은 "탈퇴한 사용자"(보는 사람이 정한 호칭이 있으면 그 호칭)로 보인다. 멤버 상태 컬럼은 `ACTIVE`를 유지하고 `users.deleted_at`으로 판단한다(오너 확정: 방식 a). 이 "유효 멤버" 정의는 한 곳(저장소 메서드나 뷰)에서만 하고 코드 곳곳에 조건을 흩뿌리지 않는다.
- **방장**: 탈퇴 요청 즉시 위임(ADR-0003 규칙). 복구해도 방장은 돌아오지 않는다.
- **복구 시 상한 충돌(Root 가정, 오너 확인 중)**: 복구 시점에 그 그룹이 이미 20명이면 그 그룹의 멤버십은 `LEFT`로 바꾸고(다시 입장 요청 필요) 나머지 그룹은 그대로 복구한다.
- **혼자 남은 그룹(Root 가정)**: 요청 시점에는 유지하고, 파기 시점에 해산(`DISSOLVED`)한다.
- 콘텐츠 선택(`KEEP` / `DELETE`)은 탈퇴 요청 시 저장하고 파기 시점에 실행한다. `DELETE`는 텍스트·리액션·음성(S3)을 모두 삭제한다.

## 범위
Backend
- 탈퇴 요청 개편(`DELETE /api/v1/users/me`, 콘텐츠 선택 필수): 한 트랜잭션에서 `deleted_at` 설정, 콘텐츠 선택 저장, Refresh 전체 폐기, 기기 토큰(`user_devices`) 삭제, 방장 위임.
- 유효 멤버 규칙 적용: 멤버 목록, 상한 COUNT, 방장 후보, 승인 대기 목록에서 유예 중 사용자를 제외.
- 복구(`restore`) 보완: 위 상한 충돌 규칙, 복구와 파기 시작의 조건부 UPDATE 경쟁(복구 마감 30일, 파기 시작 31일 이후, 둘 다 `WHERE` 조건으로 한쪽만 성공).
- 파기 배치: 매일 1회, ShedLock으로 서버 간 중복 방지. 사용자 1명 단위, 모든 단계 멱등, **외부 자원(S3, Apple) 먼저, DB는 마지막**. 진행 상태는 `purge_started_at` → `purged_at`. 서버가 중간에 죽으면 다음 실행이 이어서 처리한다. 처리: 콘텐츠 선택 실행(S3 음성 삭제 포함), `user_identities`·`refresh_tokens`·`user_devices` 삭제, `users`의 이름·이메일·전화번호 익명화(`PURGED`), `group_members`의 전화번호·호칭 익명화, 본인이 보는 사람이었던 `member_aliases` 삭제(타인이 정한 호칭은 유지), 혼자 남은 그룹 해산.
- Apple 토큰 해지: `AppleTokenRevoker` 인터페이스 + 재시도 큐 테이블(간격을 늘려 가며 재시도, 횟수 상한). 실제 호출은 Apple 키가 없어 이번엔 연결하지 않는다(구현체는 "미설정" 처리: 큐에 남기지 말고 건너뜀 상태로 기록). 해지 실패가 나머지 파기를 막지 않는다.
- 계정 연결: `GET /api/v1/auth/identities`, `POST /api/v1/auth/identities/{provider}`(로그인 상태에서 소셜 토큰 재검증 후 연결), `DELETE /api/v1/auth/identities/{provider}`. 이미 다른 계정에 가입된 소셜 계정이면 병합하지 않고 409로 거절(안내 문구 포함), 내 계정에 이미 연결돼 있으면 멱등 성공, 마지막 로그인 수단 해제는 409. 동시 연결은 유니크 제약을 최종 방어선으로 한다. 이메일 일치로 자동 연결하지 않는다.
- Flyway `V4`(오너 승인 필요): 탈퇴 콘텐츠 선택, `purge_started_at`, `purged_at`, 그룹 `DISSOLVED` 허용, Apple 해지 재시도 큐.

Mobile
- 탈퇴 화면: 콘텐츠 선택을 쉬운 말로 설명(상대에게 계속 보임 / 모두 지움), 30일 안에 복구할 수 있다는 안내, 확인 단계.
- 복구 화면: `ACCOUNT_PENDING_DELETION` 응답에서 `restorableUntil`을 받아 "OO일까지 복구할 수 있어요"와 복구 버튼을 보여 준다. `ApiException`이 응답의 `data`를 보존하도록 보완한다(auth 통합 검증에서 발견).
- 로그인 수단 화면: 연결된 수단 목록, 추가 연결, 해제(마지막 하나는 비활성). 접근성 규칙(루트 CLAUDE.md §5).
- 그룹 화면의 멤버 표시: 탈퇴 사용자는 "탈퇴한 사용자"로 표시하고 호칭 수정 가능(과거 답변 표시용).

## 범위 밖
실제 Apple 토큰 해지 호출, 소셜 SDK 연동, 질문·답변 기능 자체(답변 표시 로직은 해당 작업에서), 개인정보 처리방침 문서, 보안 이벤트 조회 화면, 백업 파기.

## Worker가 구현 전에 Root에 설계를 보고할 곳 (승인 후 구현)
(a) 파기 배치의 단계 순서·상태 전이·재시작 방법과 복구/파기 경쟁의 조건부 UPDATE, (b) "유효 멤버" 정의를 한 곳에 두는 방식, (c) 복구 시 상한 충돌 처리의 동시성, (d) Apple 해지 큐의 재시도·백오프.

## 수용 기준 (테스트로 표현)
- [ ] 탈퇴 요청 후: 모든 Refresh 폐기, 기기 토큰 삭제, 콘텐츠 선택 저장, 방장이면 즉시 위임(복구해도 방장 복귀 없음).
- [ ] 유예 중 사용자는 다른 멤버의 멤버 목록·승인 대기 목록에 없고, 인원 상한 COUNT와 방장 후보에서 제외된다.
- [ ] 복구하면 원래 그룹에 `ACTIVE`로 돌아오고, 그룹이 이미 20명이면 그 그룹은 `LEFT`가 된다.
- [ ] 파기: 31일 미만은 대상이 아니고, 31일 이상이면 익명화된다(이름·이메일·전화번호 제거, `user_identities`·`refresh_tokens`·`user_devices` 삭제, `PURGED`). 같은 소셜 계정으로 새 가입이 가능하고 이전 데이터와 연결되지 않는다.
- [ ] 파기 배치를 두 번 실행해도 결과가 같고, 중간 단계에서 실패해도 다음 실행이 이어서 끝낸다(실패 주입 테스트).
- [ ] `DELETE` 선택이면 텍스트·리액션·음성 삭제 호출이 일어나고, `KEEP`이면 남는다. 외부 삭제가 실패해도 DB 행이 먼저 사라지지 않는다.
- [ ] 복구와 파기 시작이 동시에 오면 정확히 한쪽만 성공한다(결정적 동시성 테스트).
- [ ] 서버 2대 시나리오: 같은 시점의 두 번 실행이 같은 사용자를 이중 처리하지 않는다.
- [ ] Apple 해지 실패가 파기를 막지 않고 재시도 큐에 기록된다.
- [ ] 계정 연결: 새 수단 연결 성공, 다른 계정에 가입된 소셜 계정은 409, 이미 내 것이면 멱등, 마지막 수단 해제는 409, 동시 연결 2건에서 행 1개.
- [ ] 모바일: 탈퇴·복구·로그인 수단 화면 위젯 테스트(한글 라벨, 56dp), `ApiException`이 `restorableUntil`을 보존.
